# מסירת התחקור אל מוח המאמן — התפר, כפי שהוא באמת (21.7, 2026-09-02)

**למי המסמך הזה.** לסוכן שעובד עכשיו על מוח המאמן (`api/personal-coach.js`,
`experiments/personal-coach/*`). התחקור עצמו **נסגר** — הוא לא בפיתוח, נותרו עליו רק בדיקות
פונקציונליות. מה שכן פתוח, ובגדול, זה **התפר**: מה בדיוק עובר מהתחקור אל המוח, באיזה מבנה,
ולאן חוזרת התשובה. המסמך הזה הוא מקור האמת לתפר הזה. כל שם קובץ, פונקציה ומפתח בו נבדק מול
הקוד ביום כתיבתו.

## 0. הדבר הראשון שצריך לדעת: התפר מנותק כרגע

```js
// admin-fixed-intake.js
var ATHLETE_AI_BUILD_ENABLED = false;
```

בעל המוצר ניתק את הבנייה האוטומטית ב-2026-09-02. כל חזרה על התחקור חייבה קרדיטים אמיתיים של
Gemini בזמן שהשלד עדיין נבנה, והלבנה שנוצרה גם עקפה את הנוהל שלו (הוא כותב → הוא מאשר → הוא
שולח). **הניתוק זמני ומכוון: המפסק הזה הוא נקודת החיבור מחדש בפרודקשן.** כל מה שהמוח יצטרך
נשמר היום על הלקוח, כדי שהחיבור מחדש יהיה הפעלת מפסק ולא בניית מסלול.

כשהמפסק כבוי, סיום התחקור יוצר **לקוח עם חודש ריק** (ראו §3). כשהוא דלוק, סיום התחקור קורא
ל-`generateIntakeBlockFromFixedPacket()` (ראו §4).

## 2. מה בדיוק יוצא מתחקור המתאמן האינדיבידואלי

### 2.1 שמונת השלבים

`FIXED_STEPS = ["profile","setup","schedule","recovery","lifts","skills","injuries","goals"]`

שינויים שנעשו ב-2026-09-02 ורלוונטיים לתוכן שמגיע למוח:

* **setup** — שתי אפשרויות בלבד, והן **סותרות זו את זו**: `functional_gym` או `other_home`
  (עם טקסט חופשי). האפשרות `conventional_gym` הוסרה. משמעות: `trainingSetup` יגיע כמשפט אחד
  קוהרנטי, לא כצירוף "גם וגם" שאי אפשר לתכנת לפיו.
* **schedule** — ימי אימון + `sessionMinutes` (20–120). אם מסומן `sessionTimesDiffer`, **אין**
  מספר יחיד: `sessionMinutes` נשמר 0 ובמקומו `sessionLimits` הוא טקסט חופשי
  ("45 min most days, Friday can be 90"). אל תניח שקיים תמיד מספר.
* **skills** — אי אפשר לעבור את השלב בלי לסמן משהו (או `All skills`). כלומר פרופיל מיומנויות
  ריק לחלוטין כבר לא יכול להגיע למוח.
* **goals** — נוסף צ'קבוקס **competitor**.

### 2.2 `fixedIntakePacket` — הטקסט שנכנס כהודעת המשתמש

נבנה ב-`CoachIntakeSync.buildFixedIntakePrompt(intakeState)`. טקסט שטוח, בסדר קבוע, שמתחיל
בשורה `FIXED INTAKE COMPLETE — build a full 5-week training brick now.` וכולל את המקטעים:

```
PROFILE:            Name / Gender / Age / Bodyweight / Experience
TRAINING SETUP:     המחרוזת שנגזרת מהבחירה היחידה
WEEKLY SCHEDULE:    Training days: Sun, Tue, Thu …   Notes: …
ACTIVE RECOVERY:    YES <יום> | NO (עם איסור מפורש להכביד על חמישי)
MACRO DELOAD PRESET: <ראו §6 — כאן יושבת אי-ההתאמה שצריך להכריע>
LIFTS / RUN:        שורה לכל הרמה שהוזנה
SKILLS:             מסומן = Rx, לא מסומן = scale
SESSION LENGTH:     "<N> minutes" או "unknown"
SESSION / SCHEDULE LIMITS: הטקסט החופשי, או "none"
INJURIES / LIMITATIONS:
GOALS:
COMPETITOR:         YES — … / no — …          ← חדש, 2026-09-02
```

שורת ה-COMPETITOR נוספה כי "מתאמן לקראת תחרות" שקבור בתוך טקסט חופשי הוא משפט שהמודל **עשוי**
לשקלל ועשוי שלא. הוא נאמר עכשיו במפורש, בשורה משלו, תמיד — גם השלילה.

### 2.3 `athleteProfileForGenerateBlock(intakeState, opts)` — האובייקט המובנה

הפרופיל נשלח **בנוסף** לטקסט, לא במקומו. המפתחות, בדיוק:

```
preferredLanguage ("en" תמיד) · gender · age · bodyweight · experience
activeRecoveryPref · activeRecoveryDay · trainingDays[] · scheduleNotes
skills{} · lifts{} · displayName · intakeComplete · profileNotes
fixedIntakePacket · coachPrefs[] · hasCurrentWeek · hasCurrentBlock
sessionLimits · sessionMinutes · sessionTimesDiffer · injuries · goals
trainingSetup · athleteId · userId · costCaps · monthlyUnitsUsed
```

`competitor` נשמר על הפרופיל המנורמל (`normalizeIntakeProfile`) ומופיע בטקסט. **אם המוח אמור
לקרוא אותו כשדה מובנה — צריך להוסיף אותו במפורש ל-`athleteProfileForGenerateBlock`.** היום הוא
לא שם.

## 3. מה קורה היום, כשהמפסק כבוי

`finishAdminFixedIntakeAndBuild()` → `createAthleteAsClient()`:

`POST /api/client-program`

```json
{ "action": "create",
  "clientKind": "athlete",
  "clientName": "<displayName>",
  "athleteIntake": {
    "displayName","gender","age","bodyweight","experience","trainingSetup",
    "trainingDaysMap": { "sun": true, "tue": true },
    "sessionMinutes","sessionTimesDiffer","sessionLimits","activeRecoveryPref",
    "lifts","skills","skillsSummary","injuries","goals","competitor",
    "fixedIntakePacket",   // ← החבילה המלאה, נשמרת כלשונה
    "profileNotes"
  } }
```

בשרת (`api/client-program.js`, `action === "create"`):

1. מ-`trainingDaysMap` נגזר `restDays` — **כל יום שלא סומן הוא יום מנוחה**.
2. נבנה intake-צל דרך `Intake.normalizeIntake({...})` עם
   `deloadWeek: true, deloadEveryWeeks: Intake.MIN_DELOAD_EVERY (=4)`,
   `population: "Individual athlete"`, `goals`, `sessionMinutes`.
3. `weekCount = Intake.weekCountFor() === 4`.
4. `store.createProgram(...)` יוצר תוכנית עם 4 שבועות **ריקים**, וכל יום אימון מסומן
   `ownerUnreviewed: true`.
5. `draft.athleteIntake = athleteIntake` — כאן שמורה חבילת התחקור.

`athleteIntake` נמצא ברשימת `NEVER_TO_CLIENT` ב-`lib/client-view-payload.js` — הוא לא עוזב את
השרת לכיוון הלקוח, לעולם.

**המשמעות לתפר:** היעד של לבנה שהמוח יבנה **אינו עוד ה-snapshot של המתאמן**. הוא
`program.weeks[]` של תוכנית לקוח.

## 4. מה יקרה כשהמפסק יידלק — קריאת ה-generate, מפתח במפתח

`generateIntakeBlockFromFixedPacket()` → `POST /api/personal-coach`:

```json
{ "action": "generate_block",
  "messages": [ { "role": "user", "text": "<fixedIntakePacket, חתוך ל-6000 תווים>" } ],
  "athleteProfile": { ...§2.3... },
  "athleteId": "a_<12 hex>",
  "costCaps": { "monthlyUnits": { "2026-09": <n> } },
  "intakeBuildId": "ib_<athleteId>_<timestamp>",
  "intakeComplete": true,
  "forceJson": true,
  "adminProgramming": true }
```

* **הרשאה:** כותרות אדמין (`X-Admin-Token` או `X-Admin-Password`). מאז 2026-09-02 הבדיקה היא
  `adminIsAuthed()` — קודם היא בדקה סיסמה גולמית וסירבה אחרי כל כניסה תקינה.
* **טיימאאוט:** 180,000ms עם `AbortController`.
* **נסיון חוזר:** אחד בלבד, ורק על שגיאת רשת. **אף פעם לא על abort/timeout** — שם ייתכן
  שהלבנה כבר נבנתה בשרת, וניסיון שני הוא חיוב כפול.
* **אידמפוטנטיות:** `intakeBuildId`. אל תשנו את המשמעות שלו בלי לעדכן את הצד הזה.
* **עלות:** `BRICK_FILL_UNITS = 8` ליחידות החיוב, נרשם ב-`recordBrickFill` **רק אחרי** תשובה
  תקינה. `lib/coach-cost-caps.js` חוסם בשרת.
* **POL-020:** `generate_block` הוא Gemini בלבד. Groq הוא fallback לצ'אט ואסור בתכנות.
* **PII:** `api/personal-coach.js` מריץ `scrubMessages` / `scrubProfile` מ-`api/sanitize-pii.js`.
  החבילה מכילה שם, גיל ומשקל — כל מסלול חדש אל הספק חייב לעבור דרך אותו מסנן.

### התשובה

הצד שלנו מקבל `j.block`, ואם אין — מחפש `<<<BLOCK_JSON … BLOCK_JSON>>>` בתוך `j.text`
(`parseBlockFromText`). ואז `NormalizePprogBlock.normalize(block, null)`.

מבנה יום זהה בשני העולמות ולכן ההמרה זולה:

```js
day = { parts: [ { title: "Part A", lines: ["...", "..."] } ] }
```

בתוכנית לקוח מתווספים: `id` לכל חלק (`"w" + w + d + i`), ודגלים —
`ownerUnreviewed` (התור של הבעלים), `modified` / `coachModified` (מי שינה למי).
שבוע: `{ weekIndex, phase: "build"|"deload", theme, summaryLine, overview[], days{sun..sat} }`.

## 5. הנוהל שאסור לעקוף: דגל → אישור → מסירה

זה נוהל מוצרי, לא קישוט:

1. לבנה נוצרת **לא מאושרת**. `blocks[]` מחזיק `approvedAt` לכל לבנה.
2. `approvedWeekCount(program)` הוא מה שהלקוח רשאי לראות. לבנה לא מאושרת = הלקוח לא רואה כלום.
3. כל יום אימון בלבנה חדשה נושא `ownerUnreviewed: true` — התור של הבעלים. הדגל יורד כשהוא
   **נוחת על היום** (`openDayTag` → `mark_read` עם `clearReviewed`).
4. רק אחרי אישור הבעלים מונפקים לינק וקוד, ורק אז המתאמן נכנס.

**לכן:** לבנה שהמוח יבנה חייבת להיכנס כלבנה **לא מאושרת** ועם `ownerUnreviewed` על כל יום
אימון. מוח שמייצר תוכנית שהלקוח רואה מיד שובר את הנוהל הזה, ושבירתו הייתה הסיבה המפורשת
לניתוק (2026-09-02).

## 6. אי-ההתאמה שצריך להכריע לפני שמדליקים את המפסק

**החבילה אומרת 5 שבועות. המוצר הוא 4.**

* החבילה: `"build a full 5-week training brick"`, `"Return <<<BLOCK_JSON>>> with exactly 5
  weeks"`, ו-`MACRO DELOAD PRESET: Week 5 … is a deload week by default`.
* המוצר מאז 2026-09-01: לבנה = חודש = **4 שבועות** (`Intake.weekCountFor() === 4`), והדילואד
  הוא **קצב ולא סוף בלוק** — `isDeloadWeek` בודק `absoluteWeekIndex % deloadEveryWeeks === 0`
  על מונה **רציף לאורך החודשים**, מינימום 4 (`MIN_DELOAD_EVERY`). זו הייתה דרישה מפורשת:
  "המוצר שאנחנו מוכרים הוא חודשי… בפעם הבאה שמתחיל חודש חדש הוא נפתח בשבוע דילואד".

אם ידליקו את המפסק כמו שהוא, המוח יחזיר 5 שבועות לתוך תוכנית של 4, והדילואד שלו יישב במקום
הלא נכון ביחס למונה הרציף. **ההכרעה היא מוצרית ולכן של בעל המוצר** — שתי הדרכים סבירות:

* **א׳ — לשנות את החבילה:** לבקש 4 שבועות, ולהעביר את מיקום הדילואד כעובדה
  (`deloadWeekIndexInThisBlock`) במקום כ"שבוע 5". דורש עדכון של `buildFixedIntakePrompt`
  ושל כללי ה-POL שמדברים על לבנת 5 שבועות.
* **ב׳ — להשאיר 5 ולמפות:** לקבל 5 שבועות ולמפות 4 מהם לתוכנית. פשוט יותר בצד המוח, אבל
  זורק שבוע שהמאמן כתב — ולפי כלל איכות התכנות זה בדיוק מה שאסור לעשות בשקט.

**המלצתי: א׳.** לפי `.cursor/rules/workout-quality-never-compromise.mdc`, פלט שנזרק הוא פלט
שנבנה על סמך הנחה שגויה — עדיף לתקן את השאלה מאשר לחתוך את התשובה.
